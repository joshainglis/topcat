# Rust 2024 Edition Clippy Patterns

## Overview

Topcat uses Rust 2024 edition (early adoption). This document covers clippy patterns and lints specific to or affected by the 2024 edition.

## Edition-Specific Lints

### Edition 2024 Features

Rust 2024 includes several new features that affect clippy:

1. **RPIT (Return Position Impl Trait) improvements**
2. **Never type (`!`) stabilization**
3. **Async improvements**
4. **Pattern matching enhancements**

## Common 2024 Edition Warnings

### manual_async_fn

**Problem**: Manually implementing async function.

```rust
// Before (2021 pattern, clippy warning in 2024)
fn fetch_data() -> impl Future<Output = Result<String, Error>> {
    async move {
        // ...
    }
}

// After (2024 pattern)
async fn fetch_data() -> Result<String, Error> {
    // ...
}
```

### manual_is_variant_and

**Problem**: Using matches! + unwrap pattern.

```rust
// Before (clippy warning)
let has_value = option.is_some() && option.unwrap() > 0;

// After (Rust 2024+)
let has_value = option.is_some_and(|x| x > 0);
```

### redundant_pattern

**Problem**: Unnecessary pattern matching.

```rust
// Before (clippy warning)
match value {
    x => x,
}

// After (fixed)
value
```

## RPIT (Return Position Impl Trait)

### Using RPIT Effectively

```rust
// Good: Clear return type
fn get_names() -> impl Iterator<Item = String> {
    nodes.into_iter().map(|n| n.name)
}

// Avoid: Overly complex RPIT
fn complex_return() -> impl Iterator<Item = Result<impl Display, Box<dyn Error>>> {
    // Too complex - consider type alias
}
```

### Type Alias for Complex RPIT

```rust
// Better
type NodeIterator = impl Iterator<Item = String>;

fn get_names() -> NodeIterator {
    nodes.into_iter().map(|n| n.name)
}
```

## Never Type (`!`)

### Diverging Functions

```rust
// Good: Explicit never type
fn exit_with_error(msg: &str) -> ! {
    eprintln!("Error: {}", msg);
    std::process::exit(1);
}

// Pattern: Functions that never return
fn infinite_loop() -> ! {
    loop {
        // ...
    }
}
```

### Result with Never Type

```rust
// When error case is impossible
fn always_succeeds() -> Result<String, !> {
    Ok("success".to_string())
}

// Usage
let value = always_succeeds().into_ok();  // No error handling needed
```

## Pattern Matching Enhancements

### if let chains (Rust 2024)

```rust
// Before (nested if let)
if let Some(config) = get_config() {
    if let Some(value) = config.get_value() {
        process(value);
    }
}

// After (if let chains - Rust 2024)
if let Some(config) = get_config()
    && let Some(value) = config.get_value()
{
    process(value);
}
```

### let-else statements

```rust
// Before
let config = match get_config() {
    Some(c) => c,
    None => return Err(Error::NoConfig),
};

// After (let-else - Rust 2021+, improved in 2024)
let Some(config) = get_config() else {
    return Err(Error::NoConfig);
};
```

## Iterator Improvements

### try_collect

```rust
// Before
let results: Vec<_> = items
    .iter()
    .map(|x| parse(x))
    .collect::<Result<Vec<_>, _>>()?;

// After (if available in 2024)
let results: Vec<_> = items
    .iter()
    .map(|x| parse(x))
    .try_collect()?;
```

### is_some_and / is_ok_and

```rust
// Before (clippy warns in 2024)
if result.is_ok() && result.unwrap() > 0 {
    // ...
}

// After (Rust 2024)
if result.is_ok_and(|x| x > 0) {
    // ...
}

// Similarly for Option
if option.is_some_and(|x| x.len() > 5) {
    // ...
}
```

## Topcat-Specific 2024 Patterns

### Config with Lifetimes

Current pattern works well with 2024 edition:

```rust
pub struct Config<'a> {
    pub input_dirs: Vec<PathBuf>,
    pub include_globs: Option<&'a [String]>,
    pub layers: &'a [&'a str],

```

No changes needed - this is idiomatic in 2024.

### Error Handling

```rust
// Current pattern (good for 2024)
pub enum TopCatError {
    Io(io::Error),
    CyclicDependency(Vec<String>),
    // ...
}

impl From<io::Error> for TopCatError {
    fn from(err: io::Error) -> Self {
        Self::Io(err)
    }
}
```

### Graph Iterators

```rust
// Good: RPIT for iterators
pub fn nodes(&self) -> impl Iterator<Item = &FileNode> {
    self.nodes.values()
}

// For complex iterators, use type alias
type DependencyIter<'a> = impl Iterator<Item = (&'a String, &'a FileNode)> + 'a;

pub fn dependencies(&self) -> DependencyIter<'_> {
    self.deps.iter()
        .filter(|(_, node)| !node.deps.is_empty())
}
```

## Edition Migration Warnings

### edition_2024_compatibility

When migrating from 2021 to 2024, clippy may warn about compatibility:

```rust
// Clippy may suggest updating patterns
#[warn(rust_2024_compatibility)]
fn old_pattern() {
    // Update patterns for 2024
}
```

Common updates:
1. Use `is_some_and` instead of `is_some() && unwrap()`
2. Use `is_ok_and` instead of `is_ok() && unwrap()`
3. Prefer async fn over manual Future impl
4. Use let-else for early returns

## Performance Improvements in 2024

### Avoid Unnecessary Allocations

```rust
// Good: Iterator without allocation
fn get_deps(&self) -> impl Iterator<Item = &String> {
    self.deps.iter()
}

// Avoid: Collecting when not needed
fn get_deps(&self) -> Vec<&String> {
    self.deps.iter().collect()  // Unnecessary allocation
}
```

### Smart Use of Cow

```rust
use std::borrow::Cow;

// Good: Cow for conditional ownership
fn process_name(name: &str, normalize: bool) -> Cow<str> {
    if normalize {
        Cow::Owned(name.to_lowercase())
    } else {
        Cow::Borrowed(name)
    }
}
```

## Best Practices for 2024

### DO

✓ Use `is_some_and` / `is_ok_and` for combined checks
✓ Use let-else for early returns
✓ Prefer async fn over manual Future
✓ Use RPIT for iterators
✓ Use type aliases for complex RPIT
✓ Update to 2024 patterns when suggested by clippy

### DON'T

✗ Mix 2021 and 2024 patterns unnecessarily
✗ Ignore edition_2024_compatibility warnings
✗ Use manual implementations when 2024 has built-in
✗ Over-complicate RPIT types

## Testing Edition-Specific Code

```rust
#[test]
fn test_is_some_and() {
    let option = Some(5);

    // Rust 2024 pattern
    assert!(option.is_some_and(|x| x > 0));
    assert!(!option.is_some_and(|x| x > 10));
}

#[test]
fn test_let_else() {
    fn parse_positive(s: &str) -> Option<i32> {
        let Ok(num) = s.parse::<i32>() else {
            return None;
        };

        if num > 0 {
            Some(num)
        } else {
            None
        }
    }

    assert_eq!(parse_positive("42"), Some(42));
    assert_eq!(parse_positive("-5"), None);
    assert_eq!(parse_positive("abc"), None);
}
```
